# CPU 仿真基线

当前基线接入紫光版 RISC-V CPU 的取指、译码、执行、寄存器写回和控制链路，顶层为 `tinyriscv_core`。模块位于 `rtl/core/`，由 `rtl/cpu.f` 统一列出，复用已有的 `exu_alu_datapath` 和 `gpr_reg`，不重复定义 ALU 或寄存器堆。

来源固定为 JerryYin777/FPGA_Competition-RISC-V_Processor-in-PGL22G 的 `00a3334d7c98f57a6d429a5e18910a7e2e88390b`。这是经过接口修正的功能基线，不是未经修改的上游性能基线，也不是本队已完成的自主 CPU。保留 IF/ID/EX 组织；取指是预取队列加代际(epoch)丢弃，直连 ROM 的专用读口，取指口每拍可以发一笔请求；数据访存走 RIB，与取指互不阻塞。整机 CPI 仍受访存停顿和分支冲刷限制，不能据此宣称每拍执行一条指令。

## 仿真范围

- 软件基础目标：RV32I、小端、ilp32；保留来源核的 M、CSR 和 trap 路径。扩展测试单独指定编译选项，不改变 RV32I 主测试。
- 复位地址：顶层参数 `RESET_PC` 默认 `0x00000000`（哈佛式 ROM 基址），测试台显式传入 ROM 基址。
- 指令存储器（ROM）：`0x00000000` 到 `0x0000ffff`，64 KiB；取指口只读、只接 CPU 的 `ibus`；
  数据口在 RIB 上，用于读 `rodata`/常量，以及 bootloader 通过 `ROM_WE` 写 app 区
- 数据存储器（RAM）：`0x10000000` 到 `0x1000ffff`，64 KiB
- 映射：ROM = s0，RAM = s1；取指不经过 RIB，RIB 的主设备 0 保留未用
- 结束约定：程序向 RAM 窗口第 0 个字 `0x10000000` 写 4 字节表示结束并上报返回值，
  因此 `tests/cpu/link.ld` 把可用 RAM 从 `0x10000004` 开始
- 仿真存储器：`tests/cpu/cpu_tb.sv`，两块独立的行为级存储模型，支持取指和数据请求延迟、
  背压及请求稳定性检查
- 程序：算术与分支、启动/BSS、访存（含"写 ROM 被忽略"）、扩展指令
- 栈顶：`0x10010000`；测试链接脚本为 `tests/cpu/link.ld`。
- 测试台完成邮箱写 1 通过，其他数为失败阶段号；这是测试保留区，不是硬件外设。

## 接口约定

两个总线口均使用同一个 `clk` 和低有效复位 `rst_n`。地址为字节地址，数据为 32 位；`sel[3:0]` 表示四个字节通道。外部返回包含目标字节的对齐 32 位读数据，核内完成 lane 选择及符号扩展。

- 请求在 `req_valid && req_ready` 的上升沿接受；等待期间 valid、地址、写数据和字节使能保持稳定。
- 每个口最多一笔未完成事务。外部必须为读和写各返回一次响应，不得对同一请求重复执行写入。
- 响应可以任意延后；**不支持在请求接受的同一个周期消费组合响应**。零等待外设应加至少一级响应寄存器，或保持响应到核的 `rsp_ready` 有效。
- 响应在 `rsp_valid && rsp_ready` 的上升沿消费；等待期间外部须保持响应和数据，消费后可立即失效。
- 分支冲刷时，已发出的取指请求会继续完成，但其响应按 epoch 丢弃。取指队列里尚未交付的指令同拍清空，标签队列保留到在途响应返回，因此 PC 和指令不会错配。
- 系统复位必须同时清理 CPU 与外部未完成事务。该接口没有事务 ID、错误返回、突发和多时钟域支持，不能直接等同 AXI。

## 为接入所做的修正

| 文件 | 修正 |
| --- | --- |
| `ifu.v` | 替换依赖旧总线切换/固定时序的取指逻辑。现在是预取队列加 epoch：一条请求在途时 PC 也能继续前进，标签队列保存 {epoch, pred_taken, pc} 让 PC 和预测位跟着指令走，重定向只换代际而不排空总线。重定向当拍就发出目标地址的请求（旧请求未握手时先让它完成）；队列空且下游这一拍就要拿走时，响应直接旁路到 `ifu_idu`，不经过队列写入再读出。BTB 预测跳转时下一笔直接从目标取。`STALL_PC` 不再阻塞取指。取指直连 ROM 的专用读口，`STALL_WINDOW` 只在取指和数据共用一条总线时才需要调小 |
| `btb.v` | 新增 32 项分支目标缓存。表项 {valid, tag, target, counter[1:0]}，索引取 PC[6:2]、tag 取 PC[31:7]。命中的表项用 2-bit 饱和计数器预测方向（`counter[1]` 为 1 时预测跳转）；同拍读写同一格做旁路。目标地址是查表读出来的，取指路径上不新增加法器 |
| `exu.v` | 分支/jal 解析时比较"跳不跳"与取指时的预测：一致就不冲刷，让取指已经填好的目标路径继续走；不一致才重定向。同一静态分支的目标地址由 PC 和立即数决定、是固定的，所以只比较方向位就足够（`jalr` 目标来自寄存器，不参与预测）。分支/jal 解析结果写回 BTB；`jalr` 不写，避免把变化的返回地址污染表项 |
| `rom.v` | 增加独立的取指读口：取指口只读、1 拍延迟，与数据口同拍访问互不阻塞。取指不再经过 rib，避免和访存抢同一笔总线事务 |
| `ifu_idu.v` | 无有效指令时插入 NOP，冲刷优先 |
| `exu_mem.v` | 每条访存指令只发一次请求；在请求阶段给出写使能；响应那一拍就写回并放行 EX，不再多等一拍 `done`（读数据在响应拍直接取总线值，其余时候用锁存值）；非对齐请求不发往外部 |
| `tinyriscv_core.v` | 参数化复位 PC；JAL/JALR 返回地址和 FENCE 后继地址使用执行中指令的 PC+4，而非译码级当前地址 |
| `exu.v` | JALR 目标地址清除 bit 0 |

## 尚未证明的范围

- 这些是本地定向/确定性随机回归，不是完整 RISC-V 架构认证或穷举验证。
- 继承的 CSR/异常模块只做了基本路径测试；异步中断、嵌套异常、非法指令、访问错误、特权规范及非对齐异常的完整语义仍需单独完善。不要宣称完整特权架构支持。
- 当前只验证对齐访存。来源 CLINT 对 load/store 非对齐使用相同 cause 等行为尚未整改，不能用本次阻止非法总线写入代替完整异常验证。
- `jtag_halt_i` 只限制取指；不是完整调试暂停协议。暂时接 0。
- `rtl/cpu.f` 与 `rtl/reusable.f` 有共同文件，创建 SoC 文件清单时应去重，不要把两份直接叠加编译。
