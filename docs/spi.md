# SPI 与屏幕 GPIO

STM32F1/F4 风格的寄存器子集：主机、8 位、MSB 先发，支持四种 CPOL/CPHA 模式。模块只产生 SCK/MOSI 并采样 MISO，CS、屏幕 DC 和 RST_N 由 GPIO 控制。

## 寄存器

通用 RIB SoC 的 SPI 基址为 `0x40002000`（外设子总线 2 号口，见 [platform.md](platform.md)）。

| 偏移 | 名称 | 读写行为 |
| --- | --- | --- |
| `0x00` | CR1 | 持续保持的配置；复位值 `0x04` |
| `0x04` | CR2 | 预留，读零，写入忽略 |
| `0x08` | SR | 硬件状态，软件写入忽略 |
| `0x0c` | DR | 低字节写入发送缓冲；低字节读取接收缓冲并清 RXNE |

CR1 的有效位：

| 位 | 名称 | 行为 |
| --- | --- | --- |
| 0 | CPHA | 0 在前沿采样，1 在后沿采样 |
| 1 | CPOL | SCK 空闲电平 |
| 2 | MSTR | 固定读 1，只实现主机 |
| 5:3 | BR | SCK = 输入时钟 / `2^(BR+1)`，对应 /2 到 /256 |
| 6 | SPE | 持续使能；写 DR 发送数据，不再逐字节写启动位 |

其他位读零，写入忽略。不实现从机、16 位、LSB 先发、硬件 NSS、IRQ 或 DMA；寄存器名称和有效位参照 STM32，不能直接作为完整 STM32 外设或 HAL 的兼容实现。

SR 的有效位：

| 位 | 名称 | 行为 |
| --- | --- | --- |
| 0 | RXNE | 接收缓冲中有未读取的字节 |
| 1 | TXE | 发送缓冲为空，可以提交下一字节 |
| 6 | OVR | 新接收字节到达时旧字节尚未读取；保留旧字节，丢弃新接收字节 |
| 7 | BSY | 正在移位，或 SPE=1 且有待发送字节 |

TXE 不代表线上发送完成。最后一个字节的第八个后沿结束后，且没有待发送字节，BSY 才清零；更改 DC 或释放 CS 前应等待 BSY=0。仅发送的显示驱动可以不处理接收数据，OVR 不会停止发送。

读取 DR 后再读取 SR 清除 OVR，SR 的该次读取返回清除前的状态。只读 SR 或写 SR 不清除 OVR。接收完成与 DR 读取同时发生时，读取返回旧字节，新字节保留为 RXNE=1。

## 缓冲与总线

发送端包含一个字节的缓冲和独立的移位寄存器，因此可同时保留正在发送的字节及下一个字节。RX 也使用独立缓冲，读取 DR 不影响 TX。串行帧之间允许短暂的空闲时钟间隔，CS 由软件保持。

- 请求只在 `req_valid && req_ready` 的时钟沿执行一次，响应寄存后返回，并保持到 `rsp_ready`。
- 发送缓冲满时，DR 写请求等待空间；不会覆盖正在发送或排队的数据。推荐软件先检查 TXE，再写 DR。
- DR 高字节的读写不会消费 RX 或提交 TX；寄存器按字地址译码，字节使能决定有效通道。
- CR1 低字节写入会等待已使能的发送队列排空，包括清 SPE、改模式和改分频；不会在半个字节内改变时序。
- SPE=0 时允许预装一个发送字节，TXE=0、BSY=0；设置 SPE 后开始发送。禁用时不要提交第二个字节，否则写请求会等待，单主设备软件无法越过该请求再使能 SPI。
- 系统复位清除配置、发送队列、接收缓冲、错误标志及未消费的总线响应。

SPI 测试覆盖四种模式 × 八档分频、00/FF/交替数据、独立 MISO 注入、发送缓冲满时等待、响应背压、RXNE/OVR、同拍读取/接收完成、配置写等待和传输中复位。它证明数字仿真行为，不证明真实屏幕、电气时序或 FPGA 上板结果。
