# 串口 bootloader

目的: 改了 C 不用重新综合。位流里固化一个小引导程序, 电脑经串口把新程序写进 ROM 再运行, 几秒完成。

## 存储布局

```
ROM 64 KiB
0x0000 ┌──────────────┐
       │   app 区     │  62 KiB, 链接脚本 sw/link.ld 的 ROM 长度 62K
       │              │  构建位流时放默认 app; bootloader 收到的新程序写在这里
0xF800 ├──────────────┤
       │  bootloader  │  2 KiB, sw/boot/, 硬件写保护 (任何写都丢弃)
0xFFFF └──────────────┘
```

- 板级顶层的 soc_top `RESET_PC = 0xF800`: 复位后先跑 bootloader。soc_top 的 RESET_PC 默认值仍是 0, 不用 bootloader 的测试台不受影响。
- 位流的 ROM 初值 = 默认 app 的镜像 (0x0000 起) + bootloader 镜像 (0xF800 起), 构建脚本拼成一个 hex。

## 硬件

**ROM 可写**: `rom.v` 加参数 `WRITABLE` (默认 0, 行为与现在完全相同)。为 1 时:
- 数据总线对 0x0000~0xF7FF 的写, 在 `we_en_i` 为 1 时按字节使能写入; `we_en_i` 为 0 时丢弃 (和现在一样正常握手)。
- 对 0xF800~0xFFFF 的写一律丢弃。
- 写入后, 下一次取指就能取到新指令 (没有 cache)。

**系统控制寄存器** `sysctl.v`, 外设子总线第 4 口 `0x4000_4000`:

| 偏移 | 名字 | 说明 |
|---|---|---|
| 0x0 | HW_ID | 只读, soc_top 参数 HW_ID |
| 0x4 | ROM_WE | 写 1 允许写 ROM app 区, 写 0 禁止; 复位为 0 |

app 平时 ROM_WE = 0, 野指针写 ROM 会被丢弃, 和以前一样。只有 bootloader 会打开它。

**break 复位**: 板级顶层在 UART_RX 管脚上计数, 连续低电平超过 `BREAK_CYCLES` (默认 10 ms, 50 MHz 下 500000) 就拉住复位,
RX 回到高电平后按现在的方式同步释放。正常数据里最长的低电平是 0x00 字节加起始位, 115200 下约 78 µs, 不会误触发。
- 计数器只用上电初值, 不受它自己产生的复位影响。
- 和复位键 (EGO1 S6、盘古 KEY1) 是"或"的关系。
- 直接看管脚 (打两拍), 不经过矩阵: 矩阵会被这个复位清空, 而且程序可能把串口改到别的脚。

## bootloader 固件 (sw/boot/)

自带链接脚本和启动代码, 直接访问 UART/sysctl 寄存器, 不链接 sw/drivers。
编译后必须不超过 2 KiB。

```
复位 → 初始化 UART 115200
  等 BOOT_WINDOW_MS (200 ms) 内收到 0x7F
    没收到 → 0x0000 处不是 0 就跳过去 (不往串口发任何字节, 不打扰 app 的输出);
             是 0 (位流没带程序) 就接着等
    收到了 → 发握手, 进入命令循环
命令循环:
  'W' 长度(4) CRC32(4) 数据(长度字节)
       → ROM_WE=1, 边收边按字写进 0x0000 起 (最后不足 4 字节用 0 补齐), ROM_WE=0
       → 回读刚写的范围算 CRC32 (和 zlib.crc32 相同: 多项式 0xEDB88320, 初值/结果取反)
       → 对上回 'K', 否则回 'E' + 板子算出的 CRC32(4)
       → 长度超过 app 区大小: 不写, 直接回 'E' + 0xFFFFFFFF
  'G'  → 跳到 0x0000
```

- 跳转前不复位外设: app 的启动代码和 uart_init 会重新初始化。
- 时间用 cycle CSR, 毫秒数按 bsp.h 的 `DELAY_CYCLES_PER_MS` (仿真里 `SIM_CYCLE_DIV` 会缩短它)。

## 协议

串口 115200 8N1。多字节数字一律低字节在前。

```
电脑                                     板子
 │── break 20 ms ───────────────────────→ 复位
 │── 0x7F (break 结束后立即发) ─────────→ bootloader 收到
 │←────────── 'A' 'M' 'B'  版本(1)=1  HW_ID(4)  app 区大小(4)=0xF800
 │── 'W' 长度(4) CRC32(4) 数据 ─────────→
 │←────────── 'K'   或   'E' CRC32(4)
 │── 'G' ───────────────────────────────→ 跳到 0x0000
 │←────────── app 的输出
```

- 发 0x7F 后 200 ms 内没收到握手: 重发一次 break + 0x7F, 还不行就报错 (多半是板上位流没有 bootloader 或串口选错)。
- 收到 'E': 重发一次 'W', 还不行就报错。

## 电脑端

板子按串口芯片识别 (FT2232 = EGO1, CP2102 = 盘古)。镜像长度补到 4 的倍数再发, CRC 按补齐后的数据算。
