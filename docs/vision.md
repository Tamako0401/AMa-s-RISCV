# 视觉输入

`rtl/vision/`: 把输入的图像 (现在是 HDMI 接收芯片, 以后换 OV5640) 一边收一边处理, 不存整帧。
现在做到: 收图 -> 4x4 均值缩小成 160x120 -> 存成小图, 在视频输出的小窗里显示 (见 [video.md](video.md));
同时找画面里的颜色标记, CPU 读寄存器得到它的位置。

```
MS7200 ──> hdmi_rx_adapter ──> box4 ──┬──> window_store ──> 小窗 (video.v 读)
  (以后: OV5640 ──> ov5640_adapter ──┘ └──> color_track ───> 寄存器 (CPU 读)
└────────── 输入的像素时钟 vin_pclk ──────────────┘ └ 系统时钟 ┘
```

## 像素流

各级之间都用同一组信号, 换算法只换中间某一级, 换相机只换适配器:

| 信号 | 意思 |
| --- | --- |
| `valid` | 这一拍有一个像素 |
| `sof` | 帧的第一个像素 (和 valid 同拍) |
| `eol` | 行的最后一个像素 (和 valid 同拍) |
| `data` | 像素, RGB888 (`[23:16]` R) |

- 像素按行从左上到右下; 两个像素之间可以有任意个空拍 (valid = 0)。
- 位置由下游自己数: sof 归零, 每个 valid 列加 1, eol 之后换行。
- 每级输出都是寄存器, 级与级直接相连。

## 各级

| 模块 | 做什么 | 资源 |
| --- | --- | --- |
| `hdmi_rx_adapter` | MS7200 的 de + RGB -> 像素流。de 断开超过 4096 拍算场消隐, 不管同步极性 | 几十 LUT |
| `box4` | 4x4 均值 (步长 4 的均值卷积): 横向每 4 点累加, 纵向一行 W/4 个部分和存 RAM, 满 4 行输出 | 一块 RAM |
| `window_store` | 存成 160x120 RGB332 (每像素 1 字节); 读口在系统时钟 | 160x120x8 位 |
| `color_track` | 每个点算 YCbCr 的 Cb、Cr, 和目标色都差不超过容差算命中; 一帧累加命中的个数和 x、y 之和 | 几个常数乘法和累加器 |

## 寄存器 (0x4000_5000, 外设子总线)

| 偏移 | 名字 | |
| --- | --- | --- |
| 0x00 | COLOR | 读写, 整字写: `[7:0]` Cb, `[15:8]` Cr, `[23:16]` 容差 |
| 0x04 | COUNT | 只读, 上一帧命中的点数 |
| 0x08 | SUM_X | 只读, 命中点的 x 之和 (160x120 里) |
| 0x0C | SUM_Y | 只读, 命中点的 y 之和 |
| 0x10 | FRAME | 只读, 每出一帧结果加 1 |

- 重心 = SUM / COUNT, 除法由软件做: `sw/drivers/vision.h` 的 `vision_find()`, 它会重读直到三个数来自同一帧。
- 结果在下一帧开头锁存, 比画面晚一帧。改 COLOR 的那一帧结果可能不准。
- 颜色怎么选: `model/color.py` 在画面上点选, 打印出 Cb、Cr; 硬件和它逐位相同。

盘古实测 (2026-10-21, `ama fpga report --board mes50hp`): 整个视觉输入 581 LUT / 493 FF / 3 DSP, 块 RAM 297 Kb
(其中颜色跟踪 278 LUT / 2 DSP)。小窗占 288 Kb (16 块), 实际只要 154 Kb: 19200 的深度被补成了 2 的幂。
全片块 RAM 用到 89%, 大头是 ROM (1152 Kb: 加了独立取指口后被复制成两份)。块 RAM 紧张时先改这两处
(小窗可以按 9 位宽、2048 深的块拼, 或者只存 1 位掩码)。

## 时钟

整条流水线跑在输入的像素时钟下, 只在出口跨到系统时钟:

- 小窗: 双时钟 RAM (`rtl/utils/dpram2c.v`), 写和读不同步, 读到的可能是两帧各一部分, 小窗里看不出来。
- 复位: 系统复位在 `vision.v` 里同步到像素时钟。
- 约束: `mes50hp.fdc` 按 74.25 MHz (720p) 约束输入时钟, 并声明和系统时钟不相关。

## 输入分辨率

`box4` 按 640 宽 (`vision.v` 的 `IN_W`), 640x480 正好缩成 160x120。
电脑要把盘古当显示器输出 640x480@60: 接收芯片的 EDID 里有这个分辨率 (取自厂商例程)。
输入更大时小窗只显示左上角一块。

## 芯片

- MS7200: I2C 地址 0x56, 引脚 `pins.csv` 的 HDMI_RX_*, 寄存器表和 EDID 取自盘古例程 `06_hdmi_loop`。
  初始化在 `board_hdmi_init()`; 之后主循环里要隔一阵调 `board_hdmi_poll()`, 电脑接上或换分辨率时给芯片补设置。
- 和发送芯片 MS7210 共用一个复位脚, 所以复位在 `sw/bsp/board_hdmi.h` 里一起做。
- **未上板验证**: 数据位顺序按硬件手册表 3-6 (D[23:16] = R), 初始化流程照例程。

## 算法试验

`model/` 里是 Python 试验脚本, 按硬件的方式算 (`box4` 缩到 160x120, 整数运算), 用 MediaPipe 手部 21 点当对照:

- `motion.py`: 帧差 -> 运动掩码 -> 重心, 实时看; `ablate.py`: 同一段视频跑各种组合打表。
- `color.py`: 颜色标记 (点选颜色, Cb/Cr 在容差内的点求重心)。

2026-10-21 的结论 (MacBook 摄像头, 人在电脑前挥手):

- 帧差找不准手: 脸、身体、摄像头晃动都算运动。最好的组合 (肤色 + 分格) 离手心中位数仍有 18 点 (160 宽), 跟踪门反而会锁在脸上。
- 颜色标记 (手拿红盒子) 顺光时稳定; 逆光时盒子亮面暗面断开, 重心会跳。
  红盒子 Cb=118 Cr=170 在常用肤色范围里, 但调好容差没有误识别到皮肤。
- MediaPipe 很准, 可以当老师: 以后要徒手, 用它给录的视频自动标注, 训练能放进 FPGA 的小 CNN。
