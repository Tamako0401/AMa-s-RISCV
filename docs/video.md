# 视频外设

`rtl/perips/video.v` + `video_render.v`, 挂在 RIB 从设备 2 (`0x2000_0000`)。支持 VGA 和 720p, 画面仍按 320x240 画, `video_render.v` 不变。
板顶层参数 `VIDEO_720P=1`: 1280x720@60, 每点放大 3x3 成 960x720, 左右各 160 像素黑边; `VIDEO_720P=0` 为 640x480、2x2 放大
(编译时选择, 非运行时切换)。盘古100Pro+ (`mes2l100hp_top.v`) 默认 720p; 50K 板 (`mes50hp_top.v`) 还没有 PLL, 默认 VGA。
通用 `soc_top` 默认仍为 VGA; 720p 时须传入 `video_clk`。渲染/CPU 在 50 MHz, 扫描在独立像素时钟域。

画面 = 背景图块层 + 精灵层, 颜色都经调色板; 最上面可以开一个 160x120 的小窗, 显示视觉输入 ([vision.md](vision.md))。
CPU 只改表, 像素由硬件逐行现算, 不需要整帧显存。
换到盘古 100K 后的扩展计划见 [display-plan.md](display-plan.md)。

## 地址

| 地址 | 内容 | 读写 |
| --- | --- | --- |
| `0x2000_0000` CTRL | bit0 开显示 (关时输出黑), bit1 开小窗 | 读写 |
| `0x2000_0004` SCROLL | 背景偏移: [8:0] x, [23:16] y | 读写 |
| `0x2000_0008` STATUS | bit0 场消隐期 | 只读 |
| `0x2000_000C` FRAME | 帧计数, 每帧最后一行显示完加 1 | 只读 |
| `0x2000_0010` WINDOW | 小窗左上角: [8:0] x, [23:16] y (逻辑坐标) | 读写 |
| `0x2000_1000` 调色板 | 256 项 RGB565; 下标 = 调色板号 x 16 + 色号 | 只写 |
| `0x2000_2000` 精灵 | 64 个, 每个一个字: {使能[31], 调色板号[29:26], 图块号[25:18], y[17:9], x[8:0]} | 只写 |
| `0x2000_4000` 背景 | 64 列 x 32 行, 每格一个字: {调色板号[11:8], 图块号[7:0]} | 只写 |
| `0x2000_8000` 图块 | 256 个 8x8, 每个 8 个字 (一行一个字), 左起第 i 个像素在 [4i+3:4i] | 只写 |

- 显存只能整字写, 读回 0 (读口给渲染用)。C 里用 `sw/drivers/video.h`。
- 每个图块 16 色 (4 位色号), 选 16 组调色板之一, 全屏最多 256 色。
- 精灵 16x16, 由图块 t (左上)、t+1 (右上)、t+2 (左下)、t+3 (右下) 拼成; 色号 0 透明; 编号小的盖在上面。
  x、y 按 512 回绕, 例如 y = 500 即 -12, 可以从屏幕边上出来。
- 背景 64x32 格 = 512x256 像素, 比屏幕大, SCROLL 滚动时回绕。背景色号 0 不透明。
- 建议在 FRAME 变化后更新显存 (`video_wait_frame()`); 必须赶在相应行预渲染前写完, 这不是原子换帧或无撕裂保证。

## 怎么画出来

| 模式 | 有效区 / 总尺寸 | 前肩 / 同步 / 后肩 (水平; 垂直) | 像素时钟 | 同步 |
| --- | --- | --- | --- | --- |
| VGA | 640x480 / 800x525 | 16/96/48; 10/2/33 | 25 MHz (`clk/2`), 实际 59.524 Hz | 负 |
| 720p (CEA-861) | 1280x720 / 1650x750 | 110/40/220; 5/5/20 | 74.25 MHz, 60 Hz | 正 |

- 两条 512 深的行缓存轮换 (各只用 320 点)。显示逻辑行 n 时, 渲染 n+1; 第 0 行在末尾三条物理行的消隐里预画。
  复位后的首个扫描帧输出黑色, 等预画完成再显示, 避免读未初始化的第 0 行。
- VGA 每逻辑行 3200 个系统时钟; 720p 为 `3*1650/74.25MHz = 66.667 us = 3333.33` 拍。
  最坏 `581+64*18 = 1733` 拍 (含末次 RAM 写入余量), 请求跨域再留约 4 拍, 720p 仍余约 1596 拍。
  首行预画也有 3333.33 拍; VGA 首行有 4800 拍。独立仿真实测末次写入为第 1732 拍。
- 行缓存和调色板用 `dpram2c`: 系统域写, 像素域读。行号随请求翻转保持到确认, 系统域同步请求后启动渲染;
  请求间隔至少 64 us, 大于最坏渲染时间。FRAME 通过帧事件翻转同步后在系统域计数;
  STATUS 的场消隐先在像素域寄存再双触发器同步, CPU 读到有几拍延迟。
- CTRL/WINDOW 用请求/确认快照跨到像素域; SCROLL 仍只在系统域给渲染器用。
  显存和调色板没有原子换帧, 在正在读取的位置写入仍可能撕裂, 双时钟 RAM 同址读写的颜色不保证。
- 像素域按逻辑坐标读行缓存, 下一拍查调色板, 再下一拍输出 RGB888 和对齐的同步/DE。
  小窗的 `window_store` 读口也改到扫描时钟, 数据延迟与调色板路径对齐; 黑边不显示小窗。
  数据在输出 PCLK 下降沿更新, 接收芯片在上升沿采样。

## 板级像素时钟

盘古100Pro+: `mes2l100hp_top.v` 里第二个 GTP_GPLL (`u_video_gpll`), 27 MHz -> VCO 891 -> 74.25 MHz, 没有频偏;
`ama fpga check` 会核对它的参数边界。LOCK 和系统复位一起经两级同步放开 SoC 复位。还没上板, 域间约束也没加 (见下)。

50K 板目前没有 PLL 实例。`boards/mes50hp/video_clock.vh` 单独封装时钟边界:
Verilator 用精确 74.25 MHz 行为级时钟; 非 Verilator 路径故意实例化未定义的 `MES50HP_720P_PLL_TODO`,
**补齐 IP 前不能综合 720p**。VGA 分支不实例化 PLL, 可用于回退。

需要 PDS 的 PGL50H PLL 生成配置/原语手册: 输入 50 MHz, 输出目标 74.25 MHz, 正确的复位与 LOCK 接口,
以及生成的时钟约束。当前没有可核实的整数/分数分频范围, 因而没有编造原语参数或“最接近频率”;
仿真时频偏为 0, 硬件实际频率和偏差待生成 IP 后记录。LOCK 经系统域复位链同步放开复位。
还需给输出时钟、输出数据补齐相应 generated clock、输出延迟及域间约束, 检查全部时钟 WNS 和 CDC;
原有输入 74.25 MHz 约束不能代替输出约束。不要把行号/配置快照的数据路径无条件当成普通同步路径。

## 资源

`ama fpga report --board mes50hp` 打印每个模块和全片的资源、各时钟的余量。
本次未综合。A 的行缓存仍 1024x8 = 8192 bit、调色板仍 256x16 = 4096 bit, 仅改双时钟读口:
预计新增 **0 块** DRM18K (最终以 PDS 双时钟映射结果为准); 时钟封装目标新增 **1 个 PLL**、**0 块 RAM**。
扫描/握手/同步器为寄存器与组合逻辑, 不加图像 RAM。视觉双缓冲的增量单列在 [vision.md](vision.md)。

加视觉输入之前实测 (2026-10-20): 视频 342 LUT / 278 FF, 显存 126 Kb; 50 MHz 下最差余量 +1.26 ns。

## 板上

- 盘古: MS7210 HDMI 发送芯片。视频口 (`hdmi_*`) 由 `mes50hp_top` 直连, 引脚在 `mes50hp.fdc` (硬件手册表 3-7);
  芯片的 I2C 和复位走 GPIO 矩阵 (`pins.csv` 的 HDMI_*)。上电后程序调 `board_hdmi_init()` (`sw/bsp/board_hdmi.h`)
  经软件 I2C 写寄存器, 寄存器表取自厂商例程。2026-10-21 上板出图 (640x480@60, 寄存器表不用改)。
  源码注释称 RGB888 输入、自动识别分辨率, 但 720p 未实测, 本次没有改寄存器表。
  需要原始例程或 MS7210 寄存器说明核对工作频率/同步配置, 然后实测锁定和颜色。
  MS72xx 的 16 位寄存器地址**低字节先发** (`sw/drivers/i2c.c`); 写反时"写 0x0003 再读回"的自检照样通过, 但芯片不工作。
- EGO1 没有 HDMI, 视频口不接, `board_hdmi_init()` 返回 -1。

## 仿真

- `./ama sim video_demo --frames 5`: 无窗口跑 5 帧, 写 `build/sim/video_demo-hdmi.png` (1280x720)。
  不加 `--frames` 保留交互窗口; `--vga` 改为 640x480。两种模式使用不同的仿真编译缓存。
- `tests/soc/video_sink.sv` 可设有效宽高和同步极性, `sim/view.py` 随模式保存正确尺寸 PNG。
- `./ama test tests/video/scan_tb.sv`: 两种模式核对全部像素、黑边、缩放、小窗、同步周期和宽度、FRAME/STATUS,
  并让 64 个精灵同排, 检查渲染期限, 无需固件工具链。
- `./ama test tests/soc/video_tb.sv`: 两种模式跑 `video_demo`, 核对背景、精灵透明、小窗和颜色统计。

验证记录和上板顺序见 [本次验证](hdmi-720p-validation.md)。
