# OV7670 摄像头 → HDMI（MES50HP / PGL50H）

把 OV7670 的实时画面送上板载 HDMI。本文是**用法文档**：接线、参数、`./ama` 构建下载、
状态灯判读、上板验证结果，最后附四个真实 bug 的复盘。

板卡：盘古 50K（MES50HP 核心板 + 底板，PGL50H-6-FBG484）；工具：PDS 2022.2-SP1-Lite。

## 硬件接线

摄像头模块没有 FIFO（无 RCK/RRST/RRD/WR/WRST 控制脚），直接由 FPGA 提供 XCLK 并按 PCLK 采数。

### 接口身份

- 开发板手册称该接口为 **J8**：2.54 mm 间距 40 针，34 路 IO + 1 路 5V + 2 路 3.3V + 3 路 GND
  （`MES50H-HDMI硬件指导手册v1.1.pdf` 3.5.1 节、表 3-8）。
- 底板原理图上标注为 **External_B**，器件编号 **J16**
  （`MES-HDMI-BASE-V1.1原理图.pdf` 第 5/5 张，PDF 第 7 页）。
- 两者是同一组 IO：网络名 `EX_IO_*` 与 PGL50H 管脚逐一对应。
- 所有 IO 为 **LVCMOS33**，3.3V bank。**不要接 5V**（J8-2 是 5V，只给需要 5V 的外设用）。

## 冲突与限制

- **与板载 ST7789 屏幕冲突**：[sw/bsp/shield_lcd.h](../sw/bsp/shield_lcd.h) 默认把屏幕接在
  J8_23~28（SCK=J8_27、MOSI=J8_28、CS=J8_23、DC=J8_26、RST=J8_25、BL=J8_24），
  正好是相机接线的 VS/HREF/PCLK/XCLK/D7/D6。**相机与这块屏不能同时使用**；
  需要同屏时把相机或屏幕迁到 J8_3~20 的空闲脚，并同步改 `pins.csv` 与本文。
- J8_3~20 目前空闲（34 路 IO 中剩下 18 路），后续换 FIFO 版模块或换引脚时可用。
- 相机占用 J8_21~36 后，`OV7670_MONITOR=1` 时 LED1~LED3 改作相机状态灯（见[观察与调试](#观察与调试)）。

## 电气与时序约定

- **SCCB 开漏**：FPGA 只驱动低电平，释放时呈高阻。`mes50hp.fdc` 打开了 FPGA 内部上拉
  （`PAP_IO_PULLUP`，SCL/SDA 各一路），不依赖模块上的 4.7 kΩ 电阻。
- **XCLK 由 FPGA 输出**：50 MHz 系统时钟二分频，即 25 MHz。
- **PCLK 是输入时钟域**，与系统时钟异步；`mes50hp.fdc` 里 `create_clock -name ov7670_pclk`
  按 25 MHz（40 ns）约束，位于 `io[22]`，与上表的 io 下标一致。
  PCLK 走的是**普通 IO**（U8 不是专用时钟脚），所以还要 `PAP_CLOCK_ASSIGN=GENERAL` +
  `PAP_CLOCK_DEDICATED_ROUTE=FALSE`，否则 place 阶段直接报 `E:Place-0084`。
- 数据按 **RGB565、高字节在前** 采集；一个像素占两个 PCLK，HREF 有效期间成对出现。
- HS 为高有效 HREF，VS 高有效（参数 `OV7670_VSYNC_ACTIVE_LEVEL`，默认 1）。
- 采样分辨率 **640x480（VGA）**；SCCB 初始化写 VGA RGB、RGB565 和字节顺序寄存器。

## 数据通路

```
OV7670 ──PCLK/VSYNC/HREF/D[7:0]──> ov7670_rgb565_rx
                                        │ RGB888 像素流 (cam_pclk 域)
                                        ▼
                              每 4 点取 1 点 (640x480 → 160x120)
                                        ▼
                             dpram2c 帧缓存 160x120x16b = RGB565
                                        │ 读口在 pixel_clk 域
                                        ▼
                              ov7670_vga 扫描 (25 MHz, 800x525)
                                        │ 左上角 160x120 原尺寸, 其余黑
                                        ▼
                            mes50hp_top 顶层的 OV7670_MONITOR 二选一
                                        ▼
                              MS7210 ──TMDS──> 显示器
```

## 软件与参数

`sw/app/camera/app.toml` 只有一行，但三个参数都是**必须**的：

```toml
params = { OV7670_MONITOR = 1, NN = 0, UART_BREAK_RESET = 0 }
```

| 参数 | 为什么必须这么设 |
| --- | --- |
| `OV7670_MONITOR = 1` | 才实例化 `ov7670_sccb_init` / `ov7670_vga`，并把 HDMI 输出从 SoC 切到相机通路 |
| `NN = 0` | PGL50H 只有 134 块 DRM18K，handnet 加速器要占约 108 块；不关掉连 device map 都过不去。相机监看由 HDMI 直出，本来不用 NN |
| `UART_BREAK_RESET = 0` | 板上 CP2102 没接线，`UART_RX` 悬空被当成持续 break，会把整个 SoC 压在复位里 |

这几个参数是**顶层参数**：`ama` 在生成 FPGA 工程时会改写 `mes50hp_top.v` 里的默认值，
并把参数一起算进 `hwid`（位流硬件版本号）。所以带参数的位流和普通位流**不是同一个版本**，
`./ama run` 会因此提示"位流和本地源码不一致"。

## 构建与下载（`./ama`）

`ama` 用 [uv](https://docs.astral.sh/uv/) 运行，第一次自动装依赖；Linux/macOS 直接 `./ama`。
工具路径（PDS 的 `pds_shell` / `cdt_cfg_shell`）写在 `ama.local.toml`，见
[ama.local.toml.example](../ama.local.toml.example)，`./ama doctor` 核对。

### 路径 1：第一次上板 / 改了 `rtl/`、`boards/`、`sw/boot/`

```bash
./ama doctor                                  # 先确认 pds_shell / cdt_cfg_shell 找得到
./ama fpga check -b mes50hp                   # 管脚重复 / 参照库 / GPLL 参数 / SYSCLK_HZ
./ama fpga build -b mes50hp --app camera      # 约 10 分钟; 产物在 build/fpga/mes50hp-camera/
./ama fpga report -b mes50hp --app camera     # 只打印上次的资源 + 每个时钟 WNS/WHS, 不重跑
./ama fpga program -b mes50hp --app camera    # 写 QSPI flash (上电自加载) 并立即运行
```

- `--app camera` **不能省**：不带它编出来的是"只有 bootloader、参数全默认"的位流，
  `NN` 还是 1，device map 过不去，HDMI 也还是 SoC 画面。
- 只想试一次、不想动 flash：加 `--once`（只下 SRAM，断电即失）。
- `fpga build` 成功后会写一个 `.hwid` 戳；`fpga program` 会核对它，避免烧到旧位流。
- 手上已经有一个验证过的位流时，可以绕过源码版本检查直接下 SRAM：
  ```bash
  ./ama fpga program -b mes50hp --bit build/releases/ov7670_camera_50h_20261101-0702.sbit
  ```

### 路径 2：只改 C（需要串口能通）

```bash
./ama run camera -b mes50hp       # 编译 + 经 bootloader 串口下载 + 开串口终端 (Ctrl+] 退出)
./ama upload camera -b mes50hp    # 只下载, 不开终端
./ama monitor -b mes50hp          # 只开串口终端
```

**这块板现在走不通这条路**：板载 CP2102 串口没接线，`ama` 按 USB 芯片自动识别板子时
找不到串口，`run` / `upload` 会直接失败。接上 CP2102 后，改 C 就变成"几秒"而不是"10 分钟"。

### 路径 3：没有板子

```bash
./ama test tests/video/ov7670_vga_tb.sv     # 采集 / 小窗 / 彩条回退 / 窗外纯黑
./ama test tests/video/ov7670_sccb_tb.sv    # 30 条寄存器 / 90 字节序列
./ama test tests/video                      # 视频相关的全部 (含 scan_tb / input_tb)
./ama sim camera --frames 3                 # 整机仿真, 截图在 build/sim/camera-hdmi.png
```

`./ama sim camera` 能跑，是因为 `sim_binary()` 在 `app.toml` 的 params 里看到 `OV7670_MONITOR`
就选 `mes50hp` 顶层（`mes2l100hp` 没有这个参数）。仿真里没有摄像头模型，也没有 MS7210 模型，
所以输出是**收不到帧时的彩条回退画面**：左上角 8 条彩条（160x120，其余纯黑），
正好可以用来确认扫描时序和彩条通路；串口会打印 `boot` 和 `HDMI out: no answer`。

![仿真中的彩条回退画面](img/ov7670-sim-colorbar.png)

### 排错

| 现象 | 原因 / 处理 |
| --- | --- |
| `E:Place-0084` | PCLK 走普通 IO，缺 `PAP_CLOCK_ASSIGN` / `PAP_CLOCK_DEDICATED_ROUTE` 约束 |
| `hwid` 不一致，提示先 `fpga build` | 板上位流不是用当前源码 / 当前参数编的，重走路程 1 |
| `CableList is Empty` / `No devices detected` | 下载线 USB Cable II 是 FT2232H，`ftdi_sio` 占着它；见 [boards/mes2l100hp/README.md](../boards/mes2l100hp/README.md) |
| `cdt_cfg_shell` 返回 0 但没烧进去 | 它出错也返回 0；以 `configuration_tcl.log` 有无失败、`.sfc` 是否生成且非空为准 |
| SCCB"配置成功"但画面全黑 | 缺 `PAP_IO_PULLUP`，SDA 悬空读成 0，ACK 检测假通过 |
| 整块板静默：不闪灯、无串口、HDMI 无信号 | `.note.gnu.build-id` 占了复位地址，缺 `-Wl,--build-id=none` |

## 观察与调试

HDMI 数据/同步改用专用引脚后，LED1~LED7 不再复用为 HDMI 信号，可以当状态灯用。
`OV7670_MONITOR=1` 时：

| 灯 | 含义 |
| --- | --- |
| LED1 | SCCB 初始化完成（30 条全部 ACK） |
| LED2 | SCCB 出错（传感器没应答） |
| LED3 | 已经收到过完整一帧 |
| LED8 | 固件在跑：167 ms 半周期 = MS7210 I2C 应答正常；500 ms = 无应答 |

LED1~LED3 由 `mes50hp_top` 的 `g_pins` 直接驱动，和 C 代码无关；
LED8 由 `sw/app/camera/main.c` 在 `main()` 最开头就点亮（不经过 UART/I2C），
用来区分"CPU 没跑起来"和"卡在初始化里"。

这三只灯是**唯一可用的固件侧观测手段**，因为串口还没接。

## 排障复盘：四个真实 bug

### 1. ELF 的 build-id note 占住了复位地址

`app.elf` 的 `.text` 实际从 `0x24` 开始，`0x0~0x23` 是 `.note.gnu.build-id`
（`namesz=4, descsz=0x14, type=3`，正好对应 ROM 前三个字 `0x00000004 / 0x00000014 / 0x00000003`）；
bootloader 的 `.text` 同样被顶到 `0xF824`，而 `RESET_PC = 0xF800`。

结果：**CPU 一复位执行的就是 note 数据（非法指令），整块设计完全静默**——不闪灯、无串口、
HDMI 无信号，看起来像"FPGA 没启动"。

修法（[tools/ama/firmware.py](../tools/ama/firmware.py)）：链接选项加 `-Wl,--build-id=none`。
现在 `.text` 从 `0x0` 开始、bootloader 正好落在 `0xF800`。**这个修复对所有 app 都生效**，
不只是相机。

自查方法（第一个字应该是 `_start` 的第一条指令，不是 `00000004`）：

```bash
head -1 build/fw/mes50hp/camera/rom.hex
sed -n "$((0xf800/4+1))p" build/fw/mes50hp/camera/rom.hex
```

### 2. HDMI 引脚用错了板子

工程里先后存在过两套引脚定义：一套属于另一块 MES50H-HDMI **视频扩展板**，一套属于本板。
按错的那套约束时 MS7210 收不到任何视频信号，显示器只报"无信号"；但它的 I2C 仍能收到应答，
`0x0003` 写读自检照样通过，很容易误判成"配置成功"。本板正确接法见
[boards/mes50hp/mes50hp.fdc](../boards/mes50hp/mes50hp.fdc) 与 [pins.csv](../boards/mes50hp/pins.csv)。

### 3. OV7670 只写了 4 条寄存器

原来的表只有：软复位、`COM7=0x04`（RGB）、`COM15=0xD0`（RGB565）、`TSLB=0x04`。
**自动曝光（AEC）、自动增益（AGC）、自动白平衡（AWB）全都没打开**，gamma 曲线也没写，
这是画面很暗的直接原因。

现在扩到 **30 条**（[ov7670_sccb_init.v](../rtl/vision/ov7670_sccb_init.v)）：

| 组 | 寄存器 | 作用 |
| --- | --- | --- |
| 格式 | `0x12, 0x12, 0x40, 0x3A` | 软复位、RGB、RGB565 全范围、字节顺序 |
| 曝光/增益/白平衡 | `0x13 = 0xE7` | AEC + AGC + AWB + 快速跟踪 |
| 白平衡增益 | `0x6C~0x6F = 0x40` | 中性增益 |
| gamma 曲线 | `0x7B~0x8B` | 标准 17 点曲线 |
| 亮度相关 | `0x0F = 0x60`、`0x24 = 0x75`、`0x25 = 0x63`、`0x55 = 0x10` | AGC 上限放宽到 16x、AEC 目标区间、亮度偏移 |

**没有动**窗口和时序寄存器（`0x17/0x18/0x19/0x1A/0x32/0x03`），避免把已经正常的取景搞坏。
同时给 SCCB 打开了 FPGA 内部上拉（见[电气与时序约定](#电气与时序约定)）：没有上拉时 SDA
悬空、常被读成 0，**ACK 检测会假通过**，看起来"配置成功"其实什么都没写成。

### 4. 帧缓存曾经是 RGB332

最初帧缓存每像素 8 位 = RGB332，其中**蓝通道只有 2 位**——这既是颜色发黄/发绿的结构性来源，
也会把亮度低于 1/8 的像素直接截成 0（暗部全压死）。现在改成 **RGB565**
（`160x120x16b`），另加 2x 饱和数字增益（`brighten()`）。

## 已知限制与下一步

### 画面仍偏暗

已经叠加了传感器侧（AEC/AGC/AWB、AGC 上限、AEC 目标、BRIGHT）和 RTL 侧（2x 饱和增益）
两层增益，仍然偏暗，说明传感器那侧的增益/曝光写入可能没真正生效（SCCB 有 ACK 但寄存器
效果未知）。

### 红色显示成绿色

彩条证明 HDMI 通道顺序正确，所以问题在摄像头数据解释这一侧。可能是：

- 传感器实际还在 YUV422 输出（`COM7=0x04` 没生效），Y 被当成 R 解；
- RGB565 双字节顺序 / MSB 边沿采样差一个 PCLK，导致 R 通道取到 G 的位段。

**下一步需要看到实际画面才能定性**，不建议继续盲改寄存器。

### 单缓冲撕裂

帧缓存是单缓冲，帧更新时理论上会撕裂；需要无缝画面时改双缓冲（RAM 会再翻一倍，
PGL50H 在 `NN=0` 下还有余量，但要重新看 device map）。

### 没有固件串口

CP2102 没接线，`printf` 全部看不到。接上后可以拿到 `OV7670 VGA monitor ready` 这类输出，
也能做运行中调参。

### 调参效率

每次改一个数字都要走完整 PDS 流程（综合 → 布局 → 布线 → 生成位流，约 10 分钟），
剩下两个问题都是"看效果才知道"的类型。可选方向：接上串口做运行中调参（秒级）、
用板上按键循环切增益、或在 RTL 里做自动增益（统计每帧峰值自动选增益）。

## 复现命令

```bash
# 1. 静态检查 + 构建相机位流（约 10 分钟）
./ama fpga check -b mes50hp
./ama fpga build -b mes50hp --app camera
./ama fpga report -b mes50hp --app camera     # 资源 / 时序

# 2. 烧写：写 flash（上电自加载）并立即运行；只想试一次就加 --once
./ama fpga program -b mes50hp --app camera
./ama fpga program -b mes50hp --app camera --once

# 3. 已经有验证过的位流时，直接下 SRAM
./ama fpga program -b mes50hp --bit build/releases/ov7670_camera_50h_20261101-0702.sbit

# 4. 仿真（没有板子）
./ama test tests/video/ov7670_vga_tb.sv
./ama test tests/video/ov7670_sccb_tb.sv
./ama sim camera --frames 3                   # 整机: 彩条回退画面 + 串口
```
